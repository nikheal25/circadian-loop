# AGENTS.md

Guidance for coding agents working in this repository.

## What this is

A pi package that ships one extension and one skill. It lets a pi agent work
on a single goal indefinitely by breaking the work into **cycles**: work,
checkpoint to disk, sleep, wake with an empty context, continue.

```
.pi/extensions/circadian-loop/index.ts   the entire extension, one file
.pi/skills/circadian-loop/SKILL.md       routing + the protocol's rationale
.pi/skills/circadian-loop/bootstrap.md   first-run interview + file templates
test/layout.test.ts                      sleep and help screen rendering
test/status.test.ts                      loop-file parsing, against real files
assets/*.svg                             sources for the README images
```

There is no build step. pi compiles the TypeScript at load time.

## Commands

```bash
npm install
npm test          # 24 tests, no API calls, ~1s
npm run typecheck # strict tsc
```

Both must pass before any change is considered done.

## Vocabulary — this one matters

The unit of work is a **cycle**, never a "session". A cycle boundary is a
context compaction *inside* one pi session; calling a cycle a "session"
describes a mechanism this project does not use. "Session" is correct only
for pi's own machinery (`sessionManager`, `ctx.compact()`, the session file).

After editing any doc, check every occurrence of "session" and justify it as
literal pi machinery.

## Rules

- **Do not vendor pi's utilities.** `@earendil-works/pi-tui` exports
  `visibleWidth`, `truncateToWidth`, `wrapTextWithAnsi`, `sliceByColumn`.
  Import them; pi resolves these at load time. An earlier version of this
  file reimplemented 150 lines of width math for no reason.
- **Keep the extension auditable.** No network calls, no spawned processes,
  no writes outside `loop.md`, `.pi/loop/` and `loop-results/`. Reviewers
  read `index.ts` first because pi packages run with full system access.
- **Render functions stay pure.** `buildSleepCard`, `buildHelpCard`,
  `readLoopStatus` and `cycleDelta` are exported so they can be tested
  without a terminal. Never read from disk inside `render()` — it runs on
  every tick.
- **Every rendered line must be exactly the requested width.** Overlays
  composite over existing terminal content; a short line leaves a visible
  gap. The layout tests enforce this.
- **The loop must never die silently.** Any path where the wake message
  fails to send must log to `cycles.jsonl` and surface through
  `ctx.ui.notify`. This is the worst failure mode this package has.
- **Per-cycle vs cumulative metrics.** `sessionManager.getBranch()` walks
  from the branch root, so its totals are cumulative across the whole
  session. Per-cycle numbers are derived by subtraction in `cycleDelta` and
  logged under `cycle`. Never present `cumulative` as a per-cycle figure.

## Verifying pi APIs

Do not guess at pi's API surface. The installed copy has authoritative docs
and type definitions:

```
<pi-coding-agent>/docs/extensions.md   tools, events, ExtensionContext
<pi-coding-agent>/docs/tui.md          ctx.ui.custom, overlays, components

```

## Testing a real loop

Unit tests do not exercise the sleep→compact→wake path. For that, run a real
loop with short cycles and watch at least three complete:

```bash
cd ../try-circadian
pi --approve
```

Required before shipping any change to the wake mechanism.

## Git

Do not run git commands in this repository. Prepare changes on disk and let
the maintainer commit them. Never add co-author or "generated by" trailers
to commit messages.
